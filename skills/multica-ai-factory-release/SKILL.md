# Multica AI 软件工厂发布

把唯一候选版本部署到明确授权环境，验证结果并留下可恢复、可审计的记录。

## 开始前

1. 完整读取 [执行基线](references/governance-baseline.md)和 [Issue 契约](references/multica-issue-contract.md)。
2. 读取发布 Issue、父 Issue、候选 Commit/Tag/镜像、目标环境、QA / Audit 结论、迁移和回滚方案。
3. 核对任务类型为 `Release`、状态为 `todo`、依赖、环境权限、维护窗口、备份、健康检查、监控和通知责任。
4. 确认 QA / Audit 针对同一候选版本。
5. 生产环境必须有针对当前候选版本的明确人工批准。
6. 就绪条件成立时设为 `in_progress`；否则记录阻塞并设为 `blocked`。
7. 读取“自动推进”章节；`autonomous` 模式必须能够识别协调父 Issue 和编排 Agent。

`todo` 不代表平台已经验证依赖。部署前按 Issue 正文逐项核验所有 `hard` 依赖、固定候选和满足证据；不得自行豁免、解除依赖、提升状态或把 `cancelled` 当作 `done`。

## 固定候选

记录提交、标签、镜像摘要、配置版本和迁移版本。候选在 QA / Audit 后发生非机械变化时停止，返回相应门禁。

不在发布 Issue 中顺带修改业务代码。

## 预检

检查适用项：

- 容量和依赖服务；
- 配置差异和有限权限凭据；
- 备份和恢复验证；
- 迁移顺序、兼容窗口和不可逆风险；
- 监控、告警、回滚触发阈值和责任人；
- 发布窗口、通知和恢复时间目标。

不输出令牌、密码或敏感配置值。不要把高价值生产凭据写入 Issue、日志或智能体的 `custom_env`。

## 部署

- 严格按批准步骤和顺序执行。
- 记录每个关键步骤的开始/结束、操作、结果和操作者。
- 迁移前确认备份和回滚限制。
- 出现停止条件时立即停止扩大变更面。
- 不操作 Issue 未声明的环境。

## 验证

执行适用的环境健康、核心路径、接口、权限、数据完整性、队列/定时任务、日志、监控和冒烟检查。生产按计划观察关键指标。

## 回滚或交付

- 触发阈值满足时执行已批准回滚。
- 回滚后验证服务和数据，记录残余影响。
- 成功时记录实际版本、配置、迁移、验证、异常和监控窗口。
- 先发布最终交付评论，再将发布 Issue 设为 `in_review`。
- `autonomous` 模式在评论中 mention 编排 Agent，自动触发发布审计；非生产环境在门禁 PASS 后自动收尾，生产环境还必须核对当前候选的人工发布批准。
- 不自行把生产发布 Issue 设为 `done`。

## 停止条件

- 候选与 QA/Audit 版本不一致；
- 生产缺少当前候选人工批准；
- 环境、窗口、权限、备份、回滚、依赖或监控不明确；
- 不可逆迁移风险未接受；
- 出现数据完整性、安全或核心功能异常。

## 输出

1. 目标环境和授权依据；
2. 候选唯一标识；
3. 预检、备份和回滚结论；
4. 实际部署步骤与结果；
5. 迁移和验证证据；
6. 监控窗口与指标；
7. 回滚与恢复；
8. 当前环境状态、风险、下一门禁、编排 Agent mention 和是否需要人工操作。
